  • Tags 只能来自 schema.md 的 Approved Tags。

4. 当前流程 / 数据流

1. 用户输入论文链接 / PDF / 笔记
2. 读取规则schema.md + log.md 顶部
3. 人工式查重搜索 Raw/ 是否已有
4. 生成 Raw靠 prompt 对齐格式
5. 写入新 Raw + 追加 log.md

当前问题：关键约束主要靠 agent 记忆执行。ID 重复、tag 越界、section 缺失、Related Wiki 缺失、log 格式错误，通常要到写完后才发现。

5. 目标流程 / 数据流

1. 用户输入论文链接或 draft
2. Preflight先查重、识别 ID、确认只读
3. Raw Draft生成但先不落盘
4. GuardsTemplate / Tag / Related Wiki / Log
5. Review Report人确认后再写 Raw/log
新增模块它解决什么问题它不做什么
Preflight在写文件前发现重复论文、明显同题、ID 冲突。不写 Raw，不写 log。
Template Guard检查 5-section、ID、Related Wiki 和理解型元素。不批量修旧 Raw。
Tag Guard用 schema.md 检查 Tags 是否越界。不自动新增 schema tag。
Review Report把 blocking / warning / info 翻译成人能看懂的报告。默认不落盘，是否写文件由用户拍板。

行为保持不变会变化明确不做

8. End-to-End Demos

选择这个例子的原因：PaperNotes 最常见 ingest 输入是论文链接，README 也使用 arXiv / PDF / 笔记作为入口。这里用一个已存在链接和一个假想新链接，分别展示“该停”和“可继续”。

Blocked path：重复论文（应该停）

问题给人的解释
用户输入帮我 ingest 这篇论文：https://arxiv.org/abs/2510.14967
发生了什么Preflight 发现仓库已经有这篇论文：Raw/2510-igpo.md。这不是新论文。
为什么重要如果继续写，会出现第二份 Raw；后续 compile 可能重复统计同一篇论文，log.md 也会留下误导记录。
下一步怎么做打开已有 Raw 看是否够用；如果只是补充笔记，用户要明确允许 append 到已有 Raw。默认不新增 Raw，也不追加 log。
Report 摘要阻断：重复论文。这不是程序坏了，而是在保护仓库不要重复 ingest。

Success path：新论文链接通过校验

阶段给人的解释
用户输入帮我 ingest 这篇论文：https://arxiv.org/abs/2605.12345
Preflight没有在 Raw/ 找到同 arXiv ID；建议新 ID 2605-shortname。
Draftagent 先生成 Raw 草稿，不立即写入。
GuardsTemplate Guard 检查 5-section；Tag Guard 检查 schema tags；Related Wiki Guard 检查链接格式。
下一步怎么做如果 report 是 0 blocking，再允许写入 Raw/2605-shortname.md 并追加 log.md。

Warning path：缺理解型元素（要判断严重性）

情况发生了什么为什么重要下一步怎么做
缺 TagsRaw draft 没有 Tags 行。compile 时无法稳定定位概念。阻断，补 Tags 后再写入。
出现 #entropy-guidedschema 没有这个 tag。tag 漂移会让 Wiki 概念分裂。阻断，映射到 #entropy 或让用户确认新增 tag。
缺 What would break this新 Raw 少了边界条件分析。读者不知道方法什么时候会失效。新 Raw 建议 blocking；旧 Raw 只 warning，不 retrofit。
