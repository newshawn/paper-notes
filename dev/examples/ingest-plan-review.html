4. 当前流程 / 数据流

用户输入论文链接 / PDF / 笔记→ agent 读取 schema + log 顶部→ 检查 Raw 是否已有→ 生成 Raw 草稿→ 写 Raw 文件→ 追加 log.md

问题：当前约束主要靠 agent 记忆执行；缺少一个在写入前后都能复查 ID、Tags、section、理解型元素、Related Wiki 和 log 格式的结构化报告。

5. 目标流程 / 数据流

用户输入→ Preflight→ Raw Draft→ Template Guard→ Tag Guard→ Related Wiki Guard→ Review Report→ 写 Raw/log→ Post-write Check
模块职责边界
Preflight解析 arXiv ID / PDF / 标题，检查 Raw/ 是否已有相同链接、ID 或明显同题。只读 repo；发现重复时阻断。
Template Guard检查 Raw draft 是否包含 ID、TL;DR、Method、Key Results、Takeaway、Open Questions、Related Wiki。只检查草稿或新 Raw，不批量修旧 Raw。
Tag Guard从 schema.md 读取 Approved Tags，检查 draft 的 Tags: 是否越界。遇到新 tag 时提示用户确认，不自动改 schema。
Review Report把 blocking / warning / info 分类展示给人看。默认输出到终端；是否落盘待用户决定。
Post-write Check写入后确认只出现允许的文件变化，且 log.md 追加在顶部。不得触碰 Wiki/、index.md、已有 Raw。

8. End-to-End Demos

选择这个例子的原因：PaperNotes 最自然的 ingest 输入就是论文链接，README 和 dev demo 都使用 arXiv / AlphaXiv 链接作为入口。

Success path：新论文链接通过校验

阶段示例
用户输入帮我 ingest 这篇论文：https://arxiv.org/abs/2605.12345
Preflight未在 Raw/ 找到同 arXiv ID；建议新 ID 2605-shortname。
Raw Draft生成包含 ID、Tags、TL;DR、Method、Key Results、Takeaway、Open Questions、Related Wiki 的草稿。
GuardsTags 全部来自 schema；理解型元素齐全；Related Wiki 链接格式正确。
Review Report0 blocking，允许写 Raw/2605-shortname.md 并追加 log.md。

Blocked path：重复论文（为什么要停）

你看到的内容解释
用户输入帮我 ingest 这篇论文：https://arxiv.org/abs/2510.14967
系统发现了什么仓库里已经有这篇论文的笔记：Raw/2510-igpo.md。它对应的论文链接是 2510.14967，所以这不是一篇新论文。
为什么不能继续如果继续写入，会生成第二份 Raw，后续 compile 时同一篇论文可能被重复统计，也会让 log.md 多一条误导记录。
Review Report阻断：重复论文。这表示“先不要写任何文件”，不是程序坏了。
用户下一步打开已有的 Raw/2510-igpo.md 检查是否够用；如果只是想补充笔记，需要明确说“允许 append 到这篇已有 Raw”。默认不新增 Raw，也不追加 log。

Warning path：缺理解型元素

问题处理
缺 What would break this新 Raw 推荐 blocking；如果是早期旧 Raw，只报告 warning，不 retrofit。
缺 Tagsblocking：无法 compile 到稳定概念。
出现 #entropy-guidedblocking：schema 中没有；建议映射到 #entropy，或先让用户确认新增 tag。

9. Human Decisions

问题推荐答案备选不拍板时
是否新增 scripts/ingest-review.mjs？推荐新增。它把校验从自然语言记忆变成可重复检查。只写文档，不加脚本；成本低但稳定性弱。Markdown 保持 blocking，不执行。
缺理解型元素算 warning 还是 blocking？新 Raw blocking；旧 Raw warning-only。全部 warning，减少阻断；但新 ingest 质量不够稳。Markdown 保持 blocking，不执行。
Review Report 是否落盘？默认不落盘，只终端输出；成功 ingest 的摘要写进 log.md。增加 --report 输出到临时路径或 Raw/ 下指定文件。Markdown 按默认不落盘执行。
